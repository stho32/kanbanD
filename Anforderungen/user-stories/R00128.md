# User Story R00128 — Board umbenennen, archivieren und löschen

Als Mensch, der mehrere Boards pflegt,
möchte ich ein Board in der Oberfläche umbenennen, archivieren und löschen,
damit ich veraltete Boards wegräumen kann, ohne die Datei `boards/<slug>.md` von Hand zu bearbeiten und ohne Adresse, Lesezeichen oder Berichte-Cache zu zerstören.

Herstellbar über die API (kanbanD committet je Aktion): der Ordner hat die Boards „Entwicklung“ (`boards/entwicklung.md`) und „Test“ (`boards/test.md`); „Test“ hat die Karte #7 in der Spalte „Prüfen“ mit `column-owner: human`. Heute ist der 11.11.2026.

„Umschalter“ ist der Board-Umschalter in der Kopfzeile („BOARDS · boards/“). „Slug“ ist der Dateiname unter `boards/` ohne `.md` (zugleich `#/board/<slug>` und `berichte/<slug>-fieber.md`).

## US-1: Ein Board umbenennen — der Slug bleibt

- **Gegeben** `boards/entwicklung.md` (Titel „Entwicklung“) mit `berichte/entwicklung-fieber.md`
- **Wenn** ich das Board im Umschalter in „Entwicklung 2026“ umbenenne
- **Dann**:
  - zeigt der Umschalter und die Kopfzeile „Entwicklung 2026“;
  - heißt die Datei weiter `boards/entwicklung.md`, und `#/board/entwicklung` zeigt dasselbe Board;
  - liefert `GET /api/boards/entwicklung` Titel „Entwicklung 2026“ und Slug `entwicklung`;
  - ist `berichte/entwicklung-fieber.md` byte-gleich;
  - gibt es genau einen Commit „Board „Entwicklung 2026“ umbenannt“.

## US-2: Ein Board archivieren

- **Gegeben** das Board „Test“ steht in der Liste
- **Wenn** ich es im Umschalter archiviere
- **Dann**:
  - steht `archived: 2026-11-11` in `boards/test.md`, die Datei bleibt liegen;
  - fehlt „Test“ in `GET /api/boards` und im Umschalter;
  - liefern `GET /api/boards?archivierte=ja` und `GET /api/boards/test` das Board mit `archiviert: 2026-11-11`;
  - gibt es genau einen Commit.

## US-3: Ein archiviertes Board wieder hervorholen

- **Gegeben** das archivierte Board „Test“
- **Wenn** ich es im Archiv reaktiviere
- **Dann** ist der Schlüssel `archived` weg, „Test“ steht wieder in `GET /api/boards` und im Umschalter, und `GET /api/boards/test` liefert `archiviert: null`.

## US-4: Ein Board löschen — die Aufgaben bleiben

- **Gegeben** das offene Board „Test“ mit der Karte #7, das Board „Entwicklung“ daneben
- **Wenn** ich „Test“ lösche und die Bestätigung gebe
- **Dann**:
  - fehlen `boards/test.md` und `berichte/test-fieber.md`;
  - gibt es genau einen Commit;
  - fehlt „Test“ in der Liste, und die Ansicht zeigt „Entwicklung“;
  - steht die Karte #7 weiter in `GET /api/aufgaben`.

## US-5: Der Agent darf nicht über das Board an Menschen-Spalten vorbei

- **Gegeben** das Board „Test“ mit der Karte #7 in der Menschen-Spalte „Prüfen“
- **Wenn** ein Agent „Test“ archiviert oder löscht
- **Dann** antwortet der Server 403 `{fehler, spalte: "Prüfen", nummer: 7}` und keine Datei ändert sich; ein Mensch darf „Test“ archivieren und löschen, und der Agent darf „Test“ umbenennen.

## US-6: Fehlerfall — leerer Titel, unbekanntes Board, keine leere Aktion

- **Gegeben** das Board „Entwicklung“
- **Wenn** ich einen leeren Titel sende
- **Dann** antwortet der Server 400 und die Datei bleibt byte-gleich;
- **Wenn** ich ein unbekanntes Board nenne
- **Dann** antwortet der Server 404;
- **Wenn** ein `PATCH` inhaltlich nichts ändert
- **Dann** entsteht kein Commit.

## US-7: Das letzte Board (unter Vorbehalt der PO-Antwort)

- **Gegeben** nur noch das Board „Entwicklung“
- **Wenn** ich es archiviere (Empfehlung: erlaubt)
- **Dann** fehlt es in der Liste, die Seite zeigt den leeren Zustand „Kein Board · neues anlegen“ ohne Fehler, und ein neues Board entsteht mit `POST /api/boards`.

## US-8: Der Bestätigungsdialog auf schmaler Breite

- **Gegeben** Fensterbreite 320 px
- **Wenn** ich im Umschalter „Löschen“ wähle
- **Dann** erscheint ein Bestätigungsdialog mit dem Boardnamen, das Fenster scrollt nicht quer, der Dialog ist per Tastatur bedienbar, und ohne Bestätigung wird nichts geschrieben.
