# User Story R00233 — Eine gescheiterte Aktion lässt den Ordner sauber, auch wenn jemand anderes Git gerade sperrt

Als Mensch, der im Ordner seines Boards nebenbei selbst mit Git arbeitet (oder als Agent, der über die API schreibt),
möchte ich, dass eine Aktion, die an einer fremden Git-Sperre scheitert, keine geänderten oder gelöschten Dateien zurücklässt,
damit mein nächster Commit nicht still den Rest einer gescheiterten Aktion enthält.

Ausgangslage jeder Story: ein Wegwerf-Ordner mit Board „fabrik“ und Karte #1 („alt“), alles committet; die Aufrufe kommen als `st` (`X-KanbanD-Wer`) über die API. „Sperre setzen“ heißt eine leere Datei `.git/index.lock` vor dem Aufruf, „Sperre entfernen“ heißt sie danach löschen; „Status leer“ heißt `git status --porcelain` liefert nichts.

## US-1: Eine Änderung scheitert an der Sperre und wird zurückgenommen (Fehlerszenario)

- **Gegeben** der Ordner mit Karte #1 und gesetzter Sperre
- **Wenn** `PATCH /api/aufgaben/1 {titel: "neu"}` ankommt
- **Dann** antwortet der Server 500, die Meldung nennt „index.lock“ und „zurückgenommen:“; nach dem Entfernen der Sperre ist der Status leer, Karte #1 heißt weiter „alt“, und es gibt keinen neuen Commit (heute ` M aufgaben/0001-alt.md`)

## US-2: Eine neu angelegte Karte verschwindet, derselbe Schlüssel legt danach an (Fehlerszenario)

- **Gegeben** der Ordner mit gesetzter Sperre
- **Wenn** `POST /api/aufgaben {titel: "halb", key: "halb-1"}` ankommt, danach die Sperre entfernt wird und derselbe `POST` erneut ankommt
- **Dann** antwortet der erste Aufruf 500 und hinterlässt keine Datei und keinen Status, der zweite 201 mit `neu: true`

## US-3: Lässt sich eine Datei nicht zurückschreiben, sagt die Meldung das, und der Rest ist trotzdem zurückgenommen (Grenze)

- **Gegeben** HEAD kennt `zu/a.md` (`alt`) und `d.md`; eine Aktion hat `zu/a.md` = `neu` geschrieben, `d.md` entfernt und `n.md` angelegt; die Sperre ist gesetzt, und der Ordner `zu/` ist nicht beschreibbar
- **Wenn** die Aktion committet werden soll
- **Dann** lautet die Meldung „… Rücknahme unvollständig: zu/a.md …“ ohne „zurückgenommen:“, `d.md` ist wieder da, `n.md` ist weg, und keine Datei `*.kanbanD-tmp` liegt im Ordner

## US-4: Eine Verknüpfung wird nicht geraten (Grenze)

- **Gegeben** HEAD kennt `x.sh` (ausführbar, `alt`) und die Verknüpfung `l.md` → `a.md`; eine Aktion hat `x.sh` = `neu` geschrieben und `l.md` durch eine gewöhnliche Datei ersetzt; die Sperre ist gesetzt
- **Wenn** die Aktion committet werden soll
- **Dann** steht `x.sh` wieder auf `alt` und ist ausführbar, `l.md` bleibt unverändert, und die Meldung nennt „l.md ließ sich nicht wiederherstellen: Art 120000“
