# User Story R00136 — Menüköpfe in role=menu ohne Überschrift

Als Mensch, der ein Menü mit Hilfstechnik bedient,
möchte ich, dass ein Menü nur aus Einträgen besteht und keine Überschrift enthält,
damit ich beim Öffnen die Menüeinträge höre und nicht in eine Struktur gerate, die es in einem Menü nicht gibt.

Herstellbar über die Oberfläche: die laufende Anwendung auf einer Wegwerf-Instanz. Ein Menü öffnet sich über die Kopfzeile („Seite ▾", „Mehr ▾", „Berichte"), als Kontextmenü einer Karte (Rechtsklick oder Menütaste) und als Menü „#<nr> auf Board legen" bzw. „Status" an einem WBS-Knoten.

„Menü" ist ein Element mit `role="menu"`; „Kopf" ist seine sichtbare erste Zeile (SEITE, MEHR, „#<nr> AUF BOARD LEGEN", STATUS <Knoten>). „Name" ist der zugängliche Name des Menüs (`aria-label` bzw. `aria-labelledby`).

## US-1: Kein Menü führt eine Überschrift

- **Gegeben** die Anwendung, ich kann jedes Menü öffnen
- **Wenn** ich ein Menü öffne
- **Dann** enthält kein Element mit `role="menu"` ein `h1`–`h6` oder `[role="heading"]`; das Menü enthält nur Einträge (`menuitem`, `menuitemradio`, `menuitemcheckbox`) und sein Kopf ist ein Element ohne Überschriftenrolle.

## US-2: Der Name und der Kopftext bleiben

- **Gegeben** die Anwendung, ich kann jedes Menü öffnen
- **Wenn** ich ein Menü öffne
- **Dann** ist sein zugänglicher Name unverändert („Seite", „Mehr", „Berichte", „#<nr> auf Board legen", „Status von <id>", Kartenmenü „#<nr> <Titel>"), und die vier Köpfe tragen denselben Text wie vor dem Bau — der STATUS-Kopf weiter mit der Knoten-ID als `mono` rechts.

## US-3: Der Kopf sieht unverändert aus

- **Gegeben** die vier Menüköpfe und die vor dem Bau an `main` gemessenen berechneten Werte
- **Wenn** ich jedes der vier Menüs öffne
- **Dann** sind Schriftgröße, Schriftstärke, Laufweite, Farbe, Höhe, Innenabstand, Hintergrund und untere Linie des Kopfes gleich diesen Werten, und der Kopf nutzt keine Breite (kein Querscrollen bei 320 px).
