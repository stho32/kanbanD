# User Story R00226: Eigene Meldung „Lesegrenze … belegt“ statt „Git antwortete nicht“

Als Betreiber `sh`, der unter Last die Commits und Diffs einer Aufgabe liest, und als Reviewer-Agent der Factory, der dieselben Endpunkte über die API liest,
möchte ich bei einem 503 lesen, ob Git zu langsam war oder ob kanbanD nur keinen freien Lesevorgang hatte,
damit ich nicht im Arbeits-Repository nach einem Fehler suche, den es nicht gibt.

Herstellbar: im Modultest mit gehaltenen Plätzen der Lesegrenze (Ausgangslage von [R00226](../R00226-behebung-meldung-lesegrenze-belegt.md), Abschnitt „Akzeptanzkriterien“). Über die API ist der Fall nur ein Wettlauf zwischen Wartenden und Haltenden; die Oberfläche wird mit einer gestellten 503-Antwort geprüft (wie `e2e/tests/r00205-ansicht-commits.spec.js:549`).

## US-1: Commit-Liste bei belegter Lesegrenze (Fehlerszenario)

- **Gegeben** alle 4 Plätze der Lesegrenze sind bis über die Frist belegt
- **Wenn** ich als Agent `GET /api/aufgaben/<nr>/commits` lese
- **Dann** bekomme ich 503 mit `{"fehler": "Lesegrenze von 4 gleichzeitigen Lesevorgängen bis zur Frist von 10 s belegt, Git nicht gestartet — keine Liste"}`, und Git wurde für diese Anfrage nicht gestartet. Heute steht dort „Git in einem Arbeits-Repository antwortete nicht innerhalb von 10 s — keine Liste“.

## US-2: Diff eines Commits und Gesamt-Diff (Fehlerszenario)

- **Gegeben** alle 4 Plätze sind bis über die Frist belegt
- **Wenn** ich `GET /api/aufgaben/<nr>/diff?commit=kd:<K1>` oder `GET /api/aufgaben/<nr>/diff` lese
- **Dann** bekomme ich je 503 mit „Lesegrenze von 4 gleichzeitigen Lesevorgängen bis zur Frist von 10 s belegt, Git nicht gestartet — kein Diff“.

## US-3: Nachfolgersuche (Fehlerszenario)

- **Gegeben** alle 4 Plätze sind bis über die Frist belegt
- **Wenn** ich `GET /api/aufgaben/<nr>/commits/kd:<K1>/nachfolger` aufrufe
- **Dann** bekomme ich 503 mit „Lesegrenze von 4 gleichzeitigen Lesevorgängen bis zur Frist von 10 s belegt, Git nicht gestartet — keine Suche nach dem Nachfolger“.

## US-4: Ein hängendes Git meldet weiter die Zeitgrenze (Gegenprobe)

- **Gegeben** die Lesegrenze ist frei, und die Frist der Anfrage ist abgelaufen, bevor Git antwortet
- **Wenn** ich einen der vier Endpunkte lese
- **Dann** bekomme ich 503 mit „… antwortete nicht innerhalb von 10 s — <Endung>“ wie bisher, nicht „Lesegrenze …“.

## US-5: Die Commit-Liste zeigt den Text wörtlich

- **Gegeben** `GET …/commits` antwortet 503 mit dem Text aus US-1
- **Wenn** ich als `sh` die Ansicht „Commits“ der Aufgabe öffne
- **Dann** lese ich „Die Commits ließen sich nicht lesen: Lesegrenze von 4 gleichzeitigen Lesevorgängen bis zur Frist von 10 s belegt, Git nicht gestartet — keine Liste (503).“ und nicht „Das Repository antwortete nicht innerhalb von 10 Sekunden“.

## US-6: Die Diff-Seite behält ihren Kopf

- **Gegeben** `GET …/diff` antwortet 503 mit dem Text aus US-2
- **Wenn** ich die Review-Seite der Aufgabe öffne
- **Dann** lese ich den Kopf „Zeitgrenze überschritten.“ und darunter „Der Diff ließ sich nicht lesen: Lesegrenze von 4 gleichzeitigen Lesevorgängen bis zur Frist von 10 s belegt, Git nicht gestartet — kein Diff (503).“

## US-7: Agenten finden den zweiten 503-Fall beschrieben

- **Gegeben** das gestartete Programm
- **Wenn** ich als Agent die Endpunktliste unter `/api`, die OpenAPI-Beschreibung oder die README „Für Agenten“ lese
- **Dann** steht bei Commit-Liste, Diff und Nachfolgersuche neben „Git über 10 s“ der Fall „alle 4 Plätze der Lesegrenze bis zur Frist belegt, `fehler` beginnt mit ‚Lesegrenze‘“.
