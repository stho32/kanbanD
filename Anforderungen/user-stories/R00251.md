# User Story R00251 — Laufansicht: Commits des Laufs als Marker an ihrer Stelle, Link ins Diff

Als Betreiber, der eine Karte in der Abnahme prüft und im Lauf einer Rolle nachliest, was sie getan hat,
möchte ich jeden Commit dieses Laufs an der Stelle sehen, an der er entstand, und von dort mit einem Klick in seinen Diff springen,
damit ich zu jedem Schritt sehe, was er im Code geändert hat, ohne den Commit in der Ansicht „Commits“ zu suchen — und nie einem falschen Link folge.

Ausgangslage jeder Story wie in R00251 „Akzeptanzkriterien“, herstellbar über Git und die API: Aufgabe #1 trägt T17 und die Commits C1′, C2, C3, C5a, C5b, C6; C4 steht nur im Transkript. Mensch `sh`, Browser headless in `Europe/Berlin`.

## US-1: Commits stehen dort, wo sie entstanden

- **Gegeben** die Laufansicht von T17
- **Wenn** `sh` den Lauf von oben nach unten liest
- **Dann** steht nach dem Schritt „git add -A && git commit -q …“ eine Zeile „Commit“ mit Kurzhash und Titel von C1′, nach dem Schritt mit zwei Commits erst C2, dann C3, nach den beiden Schritten „B0004: Nacharbeit“ je der eigene Commit (C5a, C5b); nach `--amend`, `cargo test` und dem abgebrochenen Hook steht keine.

## US-2: Ein Klick führt ins Diff und zurück

- **Gegeben** die Laufansicht von T17
- **Wenn** `sh` auf die Zeile von C2 klickt und danach auf der Review-Seite „Schließen“ wählt
- **Dann** zeigt die Review-Seite „Ein Commit“ mit C2, und „Schließen“ führt zurück in denselben Lauf; mit Strg-Klick öffnet sich C2 in einer neuen Registerkarte.

## US-3: Ein Commit, der nicht an der Karte steht, wird ehrlich genannt

- **Gegeben** die Laufansicht von T17
- **Wenn** `sh` zum Schritt „[DOC] Anforderung angelegt“ kommt
- **Dann** steht dort „e5f6a7b [DOC] Anforderung angelegt“ mit „Commit nicht an der Karte“, ohne Link.

## US-4: Die Zeitachse zeigt, wann committet wurde

Ausbaustufe 2 (R00251 „Zuschnitt“, WBS B1327, nicht beauftragt): gilt erst, wenn die Ausbaustufe aktiviert ist; bis dahin bleibt die Zeitachse wie heute.

- **Gegeben** die Laufansicht von T17
- **Wenn** `sh` in der Zeitachse auf den Strich „2 Commits“ tippt, bei 320 px mit dem Finger
- **Dann** springt die Ansicht zur Zeile von C2 und setzt den Fokus sichtbar dorthin; der Strich ist mindestens so hoch wie jedes andere Bedienelement (`--kd-ziel`), mit der Tastatur erreicht `sh` alle Striche über einen Tab-Stopp und die Pfeiltasten, die Sprachausgabe nennt ihn „2 Commits, zur ersten Zeile springen“, und mit dem Filter „nur Fehler“ bleiben alle Striche und Zeilen sichtbar.

## US-5: Ohne lesbare Commits bleibt der Lauf lesbar

- **Gegeben** die Laufansicht von T17, und die Commits der Karte lassen sich nicht lesen (Fehler oder mehr als 2 s)
- **Wenn** `sh` den Lauf öffnet
- **Dann** steht der Lauf vollständig, unter der Gesamtdauer steht gedämpft „Commits der Karte nicht lesbar“, kein Fehlerbild, und nur der Commit „[DOC] Anforderung angelegt“ steht als Text.

## US-6: Fremder Text wird nie zum Link

- **Gegeben** ein Lauf, in dessen Befehlen und Ergebnissen HTML, `javascript:` und eine Zeile mit einem gefälschten Hash stehen
- **Wenn** `sh` den Lauf öffnet
- **Dann** steht dieser Text sichtbar als Text, nichts wird ausgeführt, und jeder Link eines Markers führt auf genau den Commit, den die Karte nennt.
