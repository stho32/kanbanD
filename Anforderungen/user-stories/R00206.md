# User Story R00206 — Diff eines Commits per API lesen

Als Reviewer-Agent der Factory, der einen einzelnen Commit einer Karte beurteilt, ohne Zugriff auf das Arbeits-Repository,
möchte ich mit einem Aufruf Dateiliste, Zähler, Merkmale und Hunks dieses Commits lesen und große Dateien einzeln nachladen,
damit ich die Änderung prüfen kann, ohne dass ein riesiger Commit, eine Binärdatei oder ein feindliches Repository etwas stört oder ein Programm startet.

Ausgangslage jeder Story (herstellbar mit Git und der API): Arbeits-Repository R mit K1 bis K4 auf `main`, Worktree `R-karte-1` mit W1, einem verwaisten Commit V1 und einem gelöschten Commit V2 (wie R00204), dazu auf `main` der Commit X1, der `a.txt` ändert, die Binärdatei `bild.bin` anlegt und `c.txt` unverändert in `c2.txt` umbenennt; Anwendung `kd` im Register auf R; Board „fabrik“ mit #1, an der die Verweise auf K3, W1, V1, V2, X1 stehen; Agent `entw1`, Mensch `sh`. Beispiele, Schreibweise und Zahlen wie in [R00206](../R00206-diff-eines-commits-per-api-lesen.md) und [R00204](../R00204-commit-liste-einer-karte-per-api-lesen.md).

## US-1: Text, Binärdatei und Umbenennung auf einen Blick

- **Gegeben** die Ausgangslage
- **Wenn** der Agent `GET /api/aufgaben/1/diff?commit=kd:<X1>` aufruft
- **Dann** antwortet die API mit 200 und drei Dateien: `a.txt` geändert (plus 1, minus 1, mit Patch-Text), `bild.bin` neu und `binaer`, `c2.txt` umbenannt aus `c.txt` mit Ähnlichkeit 100 und ohne Patch; der Eintrag zum Commit trägt Titel, Autor, Datum und die Zahlen der Liste, und es wurde nichts geschrieben

## US-2: Auch ein verwaister Commit lässt sich lesen, ein fehlender nicht

- **Gegeben** `kd:<V1>` ist verwaist und `kd:<V2>` aus dem Repository entfernt
- **Wenn** der Agent beide Diffs liest
- **Dann** antwortet die API zu V1 mit 200 und der Datei `v.txt`, zu V2 mit 404 und dem Zustand `fehlt`; ein Verweis, der nicht an der Karte steht, ergibt 404 ohne Zustand, eine falsche Schreibweise 400

## US-3: Große Dateien kommen als Merkmal, nicht als Lücke

- **Gegeben** ein Commit mit einer Datei von 3.001 Zeilen, eine mit einer einzigen Zeile von 300.000 Zeichen und 25 Dateien zu je rund 200 KB Patch
- **Wenn** der Agent den Diff liest
- **Dann** sind die ersten beiden `gross` ohne Patch, von den 25 haben 20 einen Patch und 5 stehen als `nachladen` da, die Dateiliste ist vollständig, und jede dieser Dateien lässt sich mit `datei=` einzeln laden

## US-4: Riesige Commits füllen den Server nicht

- **Gegeben** ein Git, das für den Patch endlos Zeilen liefert, und ein Commit mit 2.001 Dateien
- **Wenn** der Agent den Diff liest
- **Dann** antwortet die API nach spätestens 15 s, das Git ist beendet, es wurde nur bis zur Grenze gelesen, und der Commit mit 2.001 Dateien zeigt 2.000 und einen Hinweis mit den Zahlen

## US-5: Fremder Inhalt ist nur Daten

- **Gegeben** Dateinamen mit Leerzeichen, Anführungszeichen, Zeilenumbruch, `<script>` und Latin-1-Bytes, ein Commit mit `<script>` im Titel und Dateiinhalt in Latin-1 mit ESC und Zeilen von 100.000 Zeichen
- **Wenn** der Agent den Diff liest (JSON und `format=patch`)
- **Dann** stehen Namen, Titel und Patch zeichengleich als Text in einer gültigen Antwort, die Patches der anderen Dateien bleiben richtig zugeordnet, nicht lesbare Bytes sind Ersatzzeichen mit `nicht_utf8`, und `datei=*` trifft keine zweite Datei

## US-6: Ein Repository mit feindlicher Konfiguration führt nichts aus

- **Gegeben** ein Arbeits-Repository, dessen Konfiguration `diff.external`, `textconv`, `core.pager`, Farben und `core.fsmonitor` auf Skripte setzt, und ein Server mit `GIT_EXTERNAL_DIFF`
- **Wenn** der Agent den Diff von X1 liest
- **Dann** läuft keines der Skripte (keine Marke), und die Antwort ist bytegleich zu der im sauberen Repository, auch wenn das Repository andere Präfixe, Kontext, Algorithmus oder Umbenennungsgrenzen eingestellt hat

## US-7: Lesen blockiert nichts und hängt nicht

- **Gegeben** ein Git, das 60 s schläft und ein Kind startet
- **Wenn** der Agent den Diff liest und währenddessen ein Mensch den Titel von #1 ändert
- **Dann** gelingt die Titeländerung in unter 1 s, der Diff antwortet nach 10 bis 15 s mit 503, danach läuft kein Prozess mehr, und es gibt keine Teilantwort

## US-8: Wiederholung kostet nichts, Bestand bleibt unberührt

- **Gegeben** ein früher gelesener Diff mit seinem `ETag` und eine Karte mit Dateien der Vorversion
- **Wenn** der Agent den Diff mit `If-None-Match` erneut liest
- **Dann** antwortet die API mit 304 ohne ein Git zu starten; die Dateien der Karte und die Commit-Zahl des Board-Ordners bleiben gleich, und `GET /api/aufgaben/1` startet weiter kein Git
