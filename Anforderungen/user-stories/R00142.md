# User Story R00142 — Karte duplizieren

Als Betreiber, der wiederkehrende Arbeit auf dem Board führt,
möchte ich eine Karte als Kopie anlegen können,
damit ich dieselbe Aufgabe nicht jedes Mal von Hand neu eintippen muss.

Gegeben in allen Szenarien: die laufende Instanz mit dem Board „entwicklung" (Spalten „Eingang", „In Arbeit", „Fertig"); Ich „EM" (Mensch) gewählt; die Aufgabe #1 „Rechnung prüfen" mit Beschreibung, drei Teilaufgaben (zwei davon erledigt), Klasse `feature`, Zuständige `[ST]`, Labels `[doku]`, Fälligkeit `2026-11-20`, Herkunft `[kd:I0005]`, einem Anhang, einem Kommentar, einem Zeiteintrag, einem laufenden Timer, einer Reservierung, einem gesetzten Signal, einem Preisetikett und einer WBS-Wirkung; #1 liegt in „In Arbeit". Alles lässt sich über die API herstellen (Muster `tests/aufgabe_anlegen.rs`).

„Duplizieren" legt aus einer Karte eine neue Aufgabe an: neue Nummer, Titel mit Zusatz „(Kopie)", die Grundfelder der Quelle — aber nichts, was an die Quelle gebunden ist (kein Fremdschlüssel, keine Zeiten, Kommentare, Durchläufe, Anhänge, kein Archivstand, keine Reservierung, kein Preisetikett, keine Signale, keine WBS-Wirkungen). Alles in **einem** Commit; Mensch und Agent dürfen duplizieren.

## US-1: Aus dem Kartenmenü duplizieren

- **Gegeben** die Karte #1 in der Spalte „In Arbeit" bei 1280 px
- **Wenn** ich im Kartenmenü „Duplizieren" wähle
- **Dann** erscheint **#2** unten in derselben Spalte „In Arbeit", die Aufgabendatei ist angelegt, und alles steht in genau einem Commit.

## US-2: Was die Kopie trägt

- **Gegeben** #1 wie im Grundbestand
- **Wenn** ich dupliziere
- **Dann** heißt #2 „Rechnung prüfen (Kopie)" und trägt dieselbe Beschreibung, drei offene Teilaufgaben (keine Haken), Klasse `feature`, Zuständige `[ST]`, Labels `[doku]`, Fälligkeit `2026-11-20` und Herkunft `[kd:I0005]`.

## US-3: Was die Kopie nicht trägt

- **Gegeben** #1 wie im Grundbestand
- **Wenn** ich dupliziere
- **Dann** hat #2 keinen Fremdschlüssel `key`, keine Zeiten, keine Kommentare, keine Durchläufe, keinen Anhangsordner, keinen Archivstand, keine Reservierung, kein Preisetikett, keine Signale, keine WBS-Wirkungen, keinen Phasen-Übersprung und keine Berichts-Zählung.

## US-4: Ohne Board duplizieren

- **Gegeben** #1 liegt auf keinem Board
- **Wenn** ich über die API `POST /api/aufgaben/1/duplizieren` ohne `board`/`spalte` sende
- **Dann** entsteht nur die Aufgabendatei der Kopie, keine Board-Zeile, und die API antwortet 201.

## US-5: Die WIP-Grenze gilt auch für die Kopie

- **Gegeben** die Spalte „In Arbeit" hat Grenze 1 und enthält #1
- **Wenn** ein Agent #1 nach „In Arbeit" dupliziert
- **Dann** wird er mit 409 „Grenze erreicht" abgewiesen und nichts wird geschrieben; ein Mensch wird durchgelassen (201).

## US-6: Eine Menschen-Spalte sperrt das Duplizieren nicht

- **Gegeben** #1 liegt in einer Spalte, die dem Menschen gehört (`column-owner: human`)
- **Wenn** ein Agent #1 dupliziert
- **Dann** gelingt es (201): die Kopie wird in die Spalte **hineingelegt**, was einem Agenten erlaubt ist; nur das Entnehmen ist ihm verwehrt.

## US-7: Die Kopie lässt sich rückgängig machen

- **Gegeben** #1 wurde gerade dupliziert (#2 ist entstanden)
- **Wenn** der Hinweis „#2 „Rechnung prüfen (Kopie)" angelegt" erscheint
- **Dann** bietet er „rückgängig" an, und „rückgängig" **archiviert** #2 — wie beim Anlegen einer Karte (R00031).

## US-8: Über Tastatur duplizieren und Fehler sehen

- **Gegeben** das Kartenmenü ist über die Tastatur geöffnet (Rechtsklick-Ersatz: Menütaste bzw. Umschalt+F10)
- **Wenn** ich „Duplizieren" per Enter auslöse und der Server mit 409 (Grenze) oder 423 (defekte Datei) antwortet oder das Netz fehlschlägt
- **Dann** wirkt der Tastaturweg wie der Mausweg, die Meldung steht sichtbar, nichts ist geändert, und es erschien keine Erfolgsmeldung vor der Antwort.
