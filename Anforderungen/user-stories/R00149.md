# User Story R00149 — Eine Karte, die der Server annimmt, ist committet oder gar nicht da

Als Agent, der Karten über die API anlegt und dabei einen Schlüssel (`key`) mitgibt,
möchte ich, dass ein angenommener `POST /api/aufgaben` entweder vollständig committet wird oder gar nichts zurücklässt,
damit meine idempotente Anlage nicht auf eine Karte zeigt, die in keiner Git-Historie steht.

Ausgangslage jeder Story: ein Wegwerf-Ordner mit Board „fabrik“ und einer Spalte; die Aufrufe kommen als Agent `bot` (`X-KanbanD-Wer`) über die API. „Genau ein Commit“ heißt `git rev-list --count HEAD` + 1; „kein Git-Rest“ heißt `git status --porcelain` leer.

## US-1: Ein Titel mit NUL-Byte legt die Karte an und committet sie (Fehlerszenario)

- **Gegeben** ein Ordner mit Board „fabrik“, und noch kein Commit für die Karte
- **Wenn** `POST /api/aufgaben {titel: "a\u0000b", key: "nul-1"}` ankommt
- **Dann** antwortet der Server 201, es entsteht genau ein Commit, `git log -1 --format=%s` ist eine Zeile ohne Steuerzeichen, die Aufgabendatei trägt den Titel `a\u0000b`, und `git status --porcelain` ist leer (heute 500, Datei vorgemerkt ohne Commit)

## US-2: Ein Titel von etwa 1 MB bleibt in der Datei, die Nachricht bleibt kurz (Fehlerszenario)

- **Gegeben** ein Ordner mit Board „fabrik“
- **Wenn** `POST /api/aufgaben {titel: <1 000 000 Zeichen>, key: "lang-1"}` ankommt
- **Dann** antwortet der Server 201, es entsteht genau ein Commit, die Commit-Nachricht ist eine Zeile mit höchstens 120 Zeichen, und die Aufgabendatei trägt den Titel ganz (heute 500, Datei vorgemerkt ohne Commit)

## US-3: Der Schlüssel findet nur eine committete Karte

- **Gegeben** eine committete Karte #1 mit `key: nul-1`
- **Wenn** derselbe `POST /api/aufgaben {titel: "a\u0000b", key: "nul-1"}` erneut ankommt
- **Dann** antwortet der Server 200 mit `neu: false` und derselben Nummer #1 — und zwar für die Karte, die in der Git-Historie steht (heute 200/`neu: false` für eine nie committete Karte)

## US-4: Eine gescheiterte Aktion hinterlässt nichts Vorgemerktes (Fehlerszenario)

- **Gegeben** ein Ordner, dessen `pre-commit`-Hook in der Testkopie `exit 1` liefert
- **Wenn** `POST /api/aufgaben {titel: "halb", key: "halb-1"}` ankommt
- **Dann** antwortet der Server 500, `git status --porcelain` ist leer, `aufgaben/0001-halb.md` existiert nicht, der Stand von `HEAD` ist unverändert, und die Meldung nennt den Pfad `aufgaben/0001-halb.md`; nach Entfernen des Hooks legt derselbe `key` **neu** an (201, `neu: true`), statt 200/`neu: false` zu melden

## US-5: Ein vorher schmutziger Pfad steht nach dem Fehlschlag auf HEAD

- **Gegeben** eine Aufgabendatei mit einer uncommitteten Änderung, und der Commit scheitert
- **Wenn** der Fehlschlag zurückgenommen wird
- **Dann** hat die Datei den Stand von `HEAD`, und `git status --porcelain` ist leer (die bewusst in Kauf genommene Schwäche aus ADR-0005 N2 Punkt 2 ist festgehalten, nicht umgangen)

## US-6: Ein Pfad außerhalb der Wurzel wird abgewiesen, ohne etwas anzufassen (Fehlerszenario)

- **Gegeben** ein Aufruf von `committen` mit dem Pfad `../x.md`
- **Wenn** die Pfadprüfung läuft
- **Dann** endet der Aufruf mit einem internen Fehler, und Index und Arbeitsbaum bleiben unberührt (zweite Linie aus ADR-0008 gilt auch in `committen`)
